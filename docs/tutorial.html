1What an agent is

An AI agent is not magic and not just another chatbot. It is a language model (LLM) that we give tools and let work in a loop: the model decides which tool to use, we actually run that function, we hand back the result, and it repeats until the task is done.

MODEL
decides
⇄
LOOP
orchestrates
⇄
TOOLS
run R

That is the difference from autocomplete: the agent acts. It can load a CSV, run a regression, see the error it got and fix itself. In this workshop we build exactly that, with your R functions as tools.

The 3 pieces, as files:

2Local models with Ollama

Ollama is a free app that lets you download and run language models on your own machine. Two things make it ideal to start with:

  • Private and offline. The model runs locally; your data never leaves your PC. Useful with sensitive clinical data, or on a plane with no wifi.
  • ChatGPT-like interface, free. With one command you get a chat in the terminal (and graphical apps if you want), without paying or creating an account.

2.1 Install Ollama

macOS / Windows Download the installer from ollama.com/download and open it. On Mac you can also: brew install ollama.
Linux 
curl -fsSL https://ollama.com/install.sh | sh

2.2 Download a model

Pick one for your laptop. For the workshop we recommend qwen2.5:3b (runs on almost any PC):

ollama pull qwen2.5:3b
ModelSizeSuggested RAMNotes
qwen2.5:3b~2 GB8 GBDefault. Fast, good tool calling.
qwen3:4b~2.6 GB8–16 GBReasons better, a bit slower.
gpt-oss:20b~13 GB16 GB+The most capable on this list.
llama3.2:3b~2 GB8 GBLightweight alternative.

2.3 Try it as a local ChatGPT

To chat directly in the terminal (no R yet):

ollama run qwen2.5:3b

Type your question and that's it. Type /bye to exit. This is just so you see the model alive; we build the real agent below.

Note: the first time you use a model, Ollama loads it into memory and the first answer takes a few seconds. The following ones are fast.

3Running the agent in R

The agent lives in R using the ellmer package (from Posit), which connects R to any model: local (Ollama) or in the cloud (Claude, etc.).

  1. Install R from cran.r-project.org (optional but handy: RStudio).
  2. Install ellmer in R: 
    install.packages("ellmer")
  3. Download this repository (green Code → Download ZIP button on GitHub, or git clone) and unzip it.
  4. Point RStudio at the folder. In RStudio: Session menu → Set Working Directory → Choose Directory… and pick 02-complete-skeleton.
  5. Run the agent. In the R console type: 
    source("agent.R")
ask("Give me Table 1 comparing by treatment, with p-values")
ask("Which variables are associated with higher mortality?")
    Full beginner, step-by-step instructions are in the repository's README.

You can also run it as a chat in the terminal:

cd 02-complete-skeleton
Rscript agent.R

The agent loads cohort.csv, calls your R functions (make_table, fit_model) and interprets the result. Table 1 is saved to table.html.

4Customising your own agent

Here's the good part: going from the empty skeleton to the working one is just filling in two files. The engine (agent.R) is not touched.

The soul (soul.md)

Who the agent is and its rules. Plain text:

You are Rho, a data-analysis assistant in R specialised in epidemiology.
You have tools that run real R code.
Rules:
 - Always use your tools; never invent numbers.
 - Load the data before analysing it.
 - Answer in English, clear and concise.

The tools (tools.R)

Each tool is an R function + a description for the model. Real example from this repo (a table with gtsummary and automatic installation):

make_table <- function(compare_by = NULL) {
  if (!requireNamespace("gtsummary", quietly = TRUE))
    install.packages("gtsummary")          # installs itself if missing
  library(gtsummary)
  data <- get_data()
  if (is.null(compare_by)) tbl <- tbl_summary(data)
  else tbl <- tbl_summary(data, by = all_of(compare_by)) |> add_p()  # comparative table + p
  tbl |> as_tibble() |> knitr::kable() |> paste(collapse = "\n")
}

tool_table <- tool(
  make_table,
  "Creates a Table 1 with gtsummary. If compare_by is given, adds p-values.",
  arguments = list(
    compare_by = type_string("Grouping variable (e.g. 'treatment').", required = FALSE)
  )
)

You register your functions in the TOOLS list and the agent can use them. That is how you adapt it to your libraries and your workflow.

Tip: make your tools robust. In this repo, if the agent forgets to load the data, the tool loads it itself. A small model makes more mistakes; a fail-safe tool saves the day.

5Claude Code CLI: the superpowers

The home-made harness teaches the concept. For real work, an off-the-shelf agent like Claude Code gives you the loop, the tools (read/write files, run commands) and a far more capable model, without programming anything.

  1. Install it, pick the command for your terminal: 
    # macOS / Linux (Terminal)
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# Windows CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

# Any system with Node.js (works everywhere)
npm install -g @anthropic-ai/claude-code

# From inside R (it shells out to your system)
system("npm install -g @anthropic-ai/claude-code")
    Windows: "claude is not recognized"? The installer put claude in %USERPROFILE%\.local\bin, but that folder isn't on your PATH yet. Run this in PowerShell, then close and reopen the terminal: 
    $userPath = [Environment]::GetEnvironmentVariable("Path", "User")
$claudePath = "$env:USERPROFILE\.local\bin"
if (($userPath -split ';') -notcontains $claudePath) {
    [Environment]::SetEnvironmentVariable("Path", "$userPath;$claudePath", "User")
}
  2. Enter the 03-claude-code folder and run claude.
  3. Ask the same thing: "Give me Table 1 comparing by treatment, with p-values."

You'll see the same skeleton, in different clothes:

Home-made harness (folders 01–02)Claude Code (folder 03)
soul.mdCLAUDE.md
tools.R.claude/skills/ + native tools
agent.R (the loop)included
local modelClaude (cloud)

The concept is identical. What changes is the polish and the reliability.

6Other tools

Antigravity Google

An agentic IDE built around the Gemini models: the agent plans, writes and runs code, and you supervise. It is Google's bet in the same direction as Claude Code. antigravity.google

Visual Studio Code + extensions

If you prefer a graphical editor, you can put the agent inside VS Code:

  • Cline and Continue: open-source agents that work with local models (Ollama) or cloud models, right in the editor.
  • GitHub Copilot: Microsoft's built-in assistant.

They are all variations on the same thing: model + tools + loop, inside the editor.

7Local vs. cloud: when to use which

Local model (Ollama)Cloud (Claude Code)
PrivacyTotal: nothing leaves your PCData goes to a server
CostFreePaid / with limits
InternetNot requiredRequired
CapabilityGood on short tasks (1–2 steps)Very high, long tasks
Best forSensitive data, learning, offlineComplex, reproducible work

The good news: it's the same skeleton. You start local to learn and for privacy, and switch to the cloud when you need more power — sometimes by changing a single line.
