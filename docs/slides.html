How we got here

From autocomplete to coding agents

Help with writing code has climbed the same ladder, from guessing the next word to running whole analyses for you.

~2000s

Autocomplete

The editor suggests the next token or function name. RStudio completion, IntelliSense. It guesses; it does not understand.

→
2021–2023

LLMs generate code

Copilot, ChatGPT. You describe it in words and get a function or a whole script. But it lives outside R, in a chat window.

→
2024–2025

LLMs inside R

Packages like ellmer (Posit) let you chat with any model from R and give it tool calling, so it runs your own R functions.

→
2025 →

Agentic systems

Claude Code and friends: agents that plan, run code, read the error, fix themselves and verify, a reproducible analysis end to end.

The jump that matters for us: the model stops being a chat on the side and starts acting inside your R session, with your data and your functions.

Part 1

What agentic AI is

The shift from a model that answers to an agent that acts, uses tools and verifies itself.

Foundations

From language model to agent

FactA language model (ChatGPT, Claude, Llama, Qwen) is excellent at predicting text: it answers, summarizes, translates and writes code.
HoweverOn its own it does not act: it does not run your R code, open your files or query your data, and it does not verify what it says. Sometimes it hallucinates.
ThereforeThe agent appears: a model + tools + memory + an orchestrator (the "harness") that lets it act, use tools and check itself, with you supervising.
A chatbot answers. An agent does tasks: it loads your data, runs the model, reads the output, reviews it and reports the result back to you.

Foundations

Anatomy of an agent

  • Model, the reasoning core. Open or closed, large or small, local or cloud.
  • Tools, run your R code, read files, search literature, query databases.
  • Memory, knows your project, your methods and your preferences.
  • Verification, checks its own answers against the data and the output.
  • Human in the loop, you approve, correct and decide. It accelerates; it does not replace your judgement.

Foundations

The harness and the working loop

The harness is the software that turns a model into an agent that works in a loop until the task is done: it perceives, reasons, uses a tool (runs code, reads your files), then verifies and reports, or repeats.

Where does the harness live?

  • In an environment you own: your own computer or server, with access only to the files you allow.
  • Sometimes you already use one: every time you open the Claude or ChatGPT app, that is a harness running for you.
In today's workshop the harness is about 50 lines of R, so you can see every moving part.
# the loop, in words
repeat {
  perceive # read your request + state
  reason # decide the next step
  use_tool # run R, read a file
  verify # check the result
  if (done) report()
}

Where can AI run?

You do not always need to send data to a public cloud. Think of it as a spectrum:

More control & privacy
More convenience & power

Local

On your computer · Ollama
Runs on your machine
Data never leaves · free · offline
Great for short, routine tasks

Cloud

API / provider · Claude, GPT
Runs in the provider's cloud
Most powerful, long tasks
Costs money · check retention
Key message: what matters is where the model runs and what happens to your data. The same R code works with either.

Agents inside R

LLMs inside R: the ellmer package

ellmer (from Posit) is the bridge: it lets you talk to any model from R, local or cloud, with one API.

  • Tool calling: register your own R functions, the model decides when to run them. That is what turns it into an agent.
  • Structured output: extract text into a typed table (great for messy clinical notes).
  • Any engine: a local model with Ollama (free, private) or Claude in the cloud, swapped in one line.
Around ellmer sit the editor assistants: chattr, gander, btw, the agent, right inside RStudio.
# chat with a LOCAL model, free
chat <- chat_ollama("qwen2.5:3b")

# give it one of your R functions
chat$register_tool(tool(
  make_table,
  "Build a Table 1 with gtsummary"
))

chat$chat("Table 1 by treatment")
#> [tool] make_table(by = "treatment")

Privacy & compliance

How your patient data stays private

Your data stays on your computer. If anything is shared, it is only de-identified results.

Your data

Stays on your computer

→
Local analysis

R on your machine

→
Results

Tables, models, figures

→
De-identify

Remove names & IDs

Option 1 · Read locally

A local model (Ollama) interprets the results. Nothing ever leaves your computer.

Option 2 · Read in the cloud

Only de-identified results travel. Use a provider under contract that does not store or train on your data.

Key message: the sensitive data stays local; only de-identified results may be shared. With a local model, even that stays home.

A tiny agent, "Rho", that analyses a synthetic clinical cohort. Everything runs on your laptop.
